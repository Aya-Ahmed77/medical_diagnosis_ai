## 2. Scraping Methodology
Each condition page is parsed by `app/scraper/parser.py`, which locates the
`<h1>` condition name and heading-anchored sections for Symptoms, Causes,
warnings/"when to get help" text, and treatment/self-care text. Pages that
match the condition URL pattern but expose none of these sections are
skipped rather than stored with empty/fabricated content.

## 3. Preprocessing
`app/preprocessing/text_cleaning.py`: lowercasing, HTML/URL stripping,
punctuation removal (hyphens preserved), a conservative custom stopword
list (negation words like "no"/"not"/"without" are deliberately **not**
removed, since they change medical meaning). The same functions run at
training time and inference time (`PreprocessingPipeline.prepare_inference_text`),
so train/inference representations never drift apart.

## 4. Problem Formulation & Dataset Statistics
Formulated as **multi-label classification** (see docstring in
`app/preprocessing/dataset_builder.py` for full justification). Because
each scraped condition page yields only one real example, additional
training rows are generated by resampling subsets of that condition's own
*real* scraped symptom phrases, and a fraction of rows are given a second,
symptom-overlapping condition as a co-label. Every generated row is tagged
`is_synthetic=True`; every field used in synthesis is real NHS Inform text,
never fabricated medical content.

## 11. Best Model Selection
Selection logic: `app/models/model_selector.py`. Composite score =
`0.5 * top_3_accuracy + 0.5 * emergency_recall`, ties broken by
`top_1_accuracy` then `f1_micro`. This is computed from whatever models
have actually been trained and evaluated — it does **not** default to
BERT/BioBERT just because it is architecturally more advanced.

## 12. Emergency Recall — Definition
A condition counts as an "emergency condition" if its scraped `warnings`
text contains one of `EMERGENCY_KEYWORDS` (e.g. "999", "A&E", "immediately",
"life-threatening") — see `app/models/evaluation.py::is_emergency_condition`.
This is a text-heuristic proxy, not a clinical severity judgement.

## 14. Limitations
- Synthetic training rows are combinatorial resamples of real scraped
  phrases, not independently verified clinical presentations.
- Emergency classification is a keyword heuristic over NHS warning text,
  not a clinical triage system.
- Deep learning / transformer results in this report are placeholders in
  this build environment (see README → Known Limitations) pending a run
  with full network/GPU/MongoDB access.
- The system is educational and explicitly not a diagnostic tool (see
  Medical Safety Disclaimer in the README and API responses).

## 15. Future Improvements
- Replace keyword-based emergency detection with a small supervised
  classifier trained on manually labeled warning text.
- Expand the scraped dataset beyond NHS Inform to add genuine
  multi-condition-per-patient training examples instead of relying purely
  on synthetic mixing.
- Add calibration (e.g. temperature scaling) to the deep learning models'
  probability outputs before ranking.
